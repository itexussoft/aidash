    Local Sessions

    Unofficial, and at your own risk. Claude Code and Codex publish no documentation for how they store sessions on disk. Everything here was worked out by reading the files themselves, so a change on either side can break it without warning. Moving, copying and deleting sessions edits those files directly. Keep your own backup of anything you cannot afford to lose.

    The Claude Code desktop app shows only the sessions its index lists under the account you are signed in as, while the transcripts themselves are shared. Drag a session onto another account to hand it over — within the same project folder, since a session belongs to the directory it ran in. The transcript does not move; only which account can see it. Restart Claude Code to pick up the change.

    A separate instance — opened from a Claude account on the Usage tab — is a second copy of Claude Desktop with its own user data folder, running beside your main one. It keeps its own index, so it gets its own columns here, drawn faintly and badged. Nothing else is split: every instance shares ~/.claude, which is what keeps a move between columns the move of one small file rather than a copy of a transcript. Merge and remove on a folder above folds its sessions back into the main profile and retires it.

    The terminal CLI ignores this index entirely: it lists whatever sits in its own config directory, for whoever is signed in. Sessions started there can therefore be missing from the desktop app altogether — those appear under Only in the CLI, and dragging one onto an account makes the desktop app list it too.

    Codex is one column rather than one per account: nothing in its storage records an account, so every session is visible to whichever account is signed in. Dragging between Codex and Claude copies the dialogue instead of moving it — the two describe conversations differently — and asks first.
